## Reference and review method

- Concept: [notebook-concept.png](design/notebook-concept.png), generated at 1536x1024. Direction: a calm professional notebook with warm paper, olive accents, serif document typography, restrained outlined tools, a narrow notebook rail, generous ruled writing space, and an open preparation/follow-up margin. The concept is a design reference, not a background image used as interactive UI.
- Latest desktop render: `%TEMP%/meeting-notebook-qa/desktop.png`, captured by the automated Chromium workflow at a 1536x1024 viewport. The full-page image is 1536x1130 because the implemented document continues below the first viewport.
- Other renders: `phone.png` at 390x844, `ipad-portrait.png` at 820x1180, and `ipad-landscape.png` at 1180x820 in the same directory. These are browser viewports, not native-device evidence.
- The concept and latest desktop render were both opened with `view_image` in the final QA pass. Phone, iPad-sized renders, and the rendered PDF were also visually inspected during implementation.
- The in-app browser was used for a real local registration, library navigation, and notebook interaction. A fresh final navigation produced no new warning/error console entries. An earlier hot-reload hook-order error was cleared by reload and did not recur in that final interaction.
- Playwright was used for repeatable pointer gestures, offline network conditions, viewport tests, and actual print/PDF generation. It supplements the visible in-app browser review.

## Above-the-fold copy review

Preserved the main development name, Work / Notebook context, Focus, Export, Meeting preparation, Prepare a meeting, Follow-ups, and the named writing tools. The following changes are intentional: Search notes instead of Search notebooks; real notebook names; Back to pages; Version history; Type; tool-specific keyboard help; current date; labeled example content; truthful sync/microphone status; and the real follow-up/important content created by the test. The generic empty follow-up sentence disappears when a question exists. Undo and Redo labels remain available to assistive technology and tooltips.

The implementation was visually checked for faithful application of the concept's notebook layout, palette, typography hierarchy, restrained controls, paper spacing, and container model. It is not pixel-identical. The functional and responsive differences above are deliberate. No clipped primary content, accidental phone title truncation, horizontal page overflow, framework overlay, or unintentional material visual mismatch remained in the inspected screens.

The verified interaction path was local sign-up, notebook/page creation, preparation, typed edits, Write ink, Mark semantic selection, editable follow-up, source correction, save/reopen, offline recovery, and export. This review does not validate live transcription, coaching, native Pencil behavior, or purchases.
